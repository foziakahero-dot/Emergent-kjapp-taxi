# Phase 4 Visual QA Matrix — quarantined Android builds

**Visual source:** `SNAR_V10_VSCode_Package.zip` (`reference/snar-v10-design/src/CustomerApp.tsx`, `DriverApp.tsx`, `index.css`, and `snar10/kit.tsx`).
**Builds:** internal Android APKs containing `https://api.kjappapp.no`. **STATIC-VISUAL-QA ONLY — PRODUCTION API EMBEDDED — NO FUNCTIONAL TESTING.**
**Capture target:** `Pixel_10` Android emulator, networking disabled before app launch. Screenshots are local evidence only.
**Status meanings:** `MATCHED` requires an actual native screenshot comparison; `PARTIAL` means comparison found a measurable non-blocking visual difference; `BLOCKED` means safe access/data/provider contract is unavailable; `NOT RUN` means the screen has not yet been captured and compared. Never infer a MATCHED state from code inspection.

`N/R` means a visual dimension has not been reviewed against an available Android native screenshot. A dash in evidence means no screenshot exists. Backend-backed states are blocked even if their route exists in the source.

## Static-only screenshot capture plan

1. Build source must be the committed Phase 4 branch/recorded SHA. Install the APK on a dedicated, clean `Pixel_10` AVD. Do not use a personal or signed-in device.
2. Before first launch, set emulator airplane mode on, disable Wi-Fi and mobile data, and verify the offline state via Android system settings/ADB. Keep the emulator offline for every capture.
3. Install/launch only after confirming no active default network. Target-package local data was cleared before launch. Capture the native splash and unauthenticated onboarding screen.
4. From onboarding, navigate only to the login presentation. Capture it without entering text or activating submit, provider, registration, password-reset or help actions. Login comparisons include layout only; do not test authentication.
5. Driver: capture splash/unauthenticated start and navigate to login presentation only. Do not enter or submit credentials.
6. Save raw PNGs beneath `artifacts/phase4-static-visual-qa/<app>/<build-id>/` locally. Record device resolution, Android API level, screenshot dimensions, build ID and capture time. Do not commit raw APKs/screenshots unless a later repository artifact policy explicitly permits them.
7. Compare each screenshot to the corresponding approved source screen at the same aspect ratio. Record numeric geometry/font/color observations and one issue ID per demonstrated mismatch. Do not label a prototype/simulated screen as a native product-state match.
8. If network isolation cannot be positively verified, stop before app launch. Do not use a screenshot from a simulator connected to production.

No Customer/Driver backend-backed states were navigated. They remain BLOCKED pending a separate staging environment and explicit functional QA authorization. Both local APKs are intentionally uncommitted; screenshots and reference renders are kept under `artifacts/phase4-static-visual-qa/`.
