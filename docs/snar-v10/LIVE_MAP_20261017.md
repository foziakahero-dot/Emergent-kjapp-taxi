# SNAR live map repair

## Implemented

- Customer opens to the live map with a small Search button at the top. Search expands to at most 30% of the current viewport height. The minimize control dismisses the keyboard and restores the map. The query survives minimize/reopen; results scroll within the panel. No dark full-screen search overlay remains. A selected booking can be minimized and resumed.
- Available supply still uses the authenticated Render Socket.IO `/customer-cars` namespace, subscribed to the customer's actual GPS circle. Manual pickup addresses do not masquerade as the customer's current location. Existing REST `/api/cars/nearby` returns the same policy.
- The backend requires online, approved, current session, non-revoked login, active fleet, valid assigned car, fresh GPS, operational compliance, no active assignment and no active trip. Explicit `available=false`, `absent`, `away`, `on_break` and non-available `availability_status` also exclude a driver, both in the initial read and the final availability fence. The client additionally rejects explicit unavailable/offline payloads.
- Each available-car marker has an upright whole-minute ETA badge on native Mapbox and web/raster fallback. Missing ETA is `ETA —`, never a synthetic speed or straight-line estimate.
- Google receives driver positions as origins and current customer GPS as destination. `duration_in_traffic` is preferred; the returned road `duration` is accepted if traffic duration is unavailable. Whole minutes round up, minimum one minute. Haversine remains only for 5km visibility filtering, never for ETA.
- Google calls run in the background: offline/busy removals and live GPS do not wait for Google. Only ETA is cached (30 seconds, ~100m coordinate cells); live driver availability/locations are never cached there. Batches contain at most 25 origins and one destination; requests in flight are deduplicated and bounded. Provider errors/quota denial cause a short backoff and unavailable ETA.

## MANUAL activation

Google Cloud Console is unavailable in this agent browser (Site Unavailable after one reload). A verified server API key was not available to configure or run real Google ETA requests.

1. In the Google Cloud project enable billing and **Distance Matrix API (Legacy)** if it is already available to that project. Create a dedicated server key, API-restricted to the selected matrix service; apply supported Render outbound-IP restrictions. Do not put this server key in Expo, Vercel public variables or app bundles.
2. Set `QA_GOOGLE_MAPS_SERVER_API_KEY` directly in Render QA. Set `QA_GOOGLE_MAPS_MATRIX_PROVIDER=distance_matrix`. Production uses the same names without `QA_`. QA never falls back to the production key.
3. Google no longer enables Distance Matrix Legacy for new projects. If this project cannot enable it, enable **Routes API** and explicitly set `QA_GOOGLE_MAPS_MATRIX_PROVIDER=routes` instead. This selects Google's official `computeRouteMatrix` with traffic-aware driving, not a straight-line approximation. It is an explicit provider choice, not a silent fallback.
4. Redeploy Render after saving variables; confirm two real online/idle cars and one offline/busy car using their real accounts. Check ETA against the same driver→customer driving route in Google Maps. Check logout, active assignment, GPS expiry and unavailable Google responses.
5. Customer/Driver Vercel projects and signed APKs need the corrected source. No Customer/Driver Vercel project was found among the three connected repo projects (admin/landing/fleet). See `GOOGLE_SIGN_IN_20261017.md` for root directories and backend configuration. No paid native builds were launched.
