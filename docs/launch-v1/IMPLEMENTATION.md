- Six root Node checks cover actual live feed recovery, search/Back/reopen, accepted Driver UI, native payment import and original assets. Six Driver checks cover server-based offer clock and truthful payment-summary dismissal.

Replaced obsolete OTP expectations with real password-handler tests, and socket assumptions with actual authenticated polling/push contracts. Financial, owner, role, revocation, 2FA, expiry and canonical lifecycle checks remain enforced.

## Production configuration and rollback

- Do not point production at QA, import QA users/cards or enable fake vehicles. `APP_ENV=production`, production database, live/test Stripe separation and mandatory Admin 2FA remain intact.
- Existing production readiness confirms live Stripe key/publishable key/webhook present. Native card UI requires the explicit `NATIVE_PAYMENTS_ENABLED` and `NATIVE_PAYMENTS_LIVE_ENABLED` flags. Apple/Google Pay are separate provider/native capability gates; absent Apple merchant configuration is not papered over with a visible button.
- Production email currently reports unconfigured. Existing Resend implementation now serves Driver/Fleet onboarding and the outbox, with escaped account names and time-limited reset tokens; verified provider/sender and actual delivery are still required. Connected Render tooling can update environment values but cannot read/recover existing secret values. No Resend connector was found. QA-prefixed credentials must never be silently reused in production.
- Customer SMS remains truthfully disabled until production Twilio Verify credentials and `CUSTOMER_OTP_ENABLED=true` are present. No hardcoded OTP, fake success or automatic attachment of ambiguous legacy phone numbers.
- No destructive schema/data migration is included. An additive TTL index expires OTP challenges. No production account/trip/fleet/commission history is rewritten.
- Render auto-deployment is disabled. Deploy the reviewed production branch after merge, then verify reported live commit, health/database, readiness and public auth/payment configuration. Prior production commit for rollback is `02ed5c061d34f80f5b255a2f270a4903aa3c271e`; disabling new card setup uses `NATIVE_PAYMENTS_ENABLED=false` while preserving existing payment recovery/webhooks.

Native/runtime provider blockers are explicit. This cycle does not declare either app ready for the separate release gate.
